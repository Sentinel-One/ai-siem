[3] Akamai exclusion rule type: SCHEDULED
    Long list, edited weekly, and you want to see what it suppresses.
    single-event and correlation bodies are boolean S1QL with NO pipes: the list
    can only be hardcoded inline in the rule body, and with no pipes there is no
    anti-join, so no effectiveness dashboard is possible for either.
    Scheduled keeps the list in a CSV lookup and the dashboard counts the exact
    inverse over the same window: | filter excl_asset = * (excluded + kept = total).

[4] RBA collector
    Two credentials, therefore two connections.
    Run Contributors -> /sdl/api/powerQuery keeps "SentinelOne SDL" (console JWT).
    Publish Risk Events -> /services/collector/event needs an SDL Log Write Key.
    Your HTTP 400 {"text":"Missing S1-Scope header","code":5} means the publish
    step carried the console token without a scope header. Adding the header
    would make the console token work on some consoles only; others refuse it
    either way with HTTP 403 "User token not allowed for this endpoint" (code 4).
    The fix is the write key in both cases. That action sends no S1-Scope header
    at all; the write key's scope is fixed when it is minted.
    Sequence: import -> POST /hyper-automate/api/v1/workflows/{id}/publish in the
    SAME step (Private Draft is invisible to you until it is a Shared Draft) ->
    you bind both connections in the console -> activate -> run-now and confirm
    fresh events query back out of dataSource.name='risk'.
